# 🛡️ HealVPN Background Payment System Audit & Verification Plan

В рамках этой задачи мы проведем полный аудит фоновой системы проверки платежей и автопродления подписок в боте HealVPN. Мы убедимся в отсутствии багов, гонок и ошибок, внедрим защитное программирование (defensive programming) для непредвиденных ответов API и напишем новые автоматизированные тесты для полной верификации.

---

## 1. Архитектурный Анализ Фоновой Системы

Фоновая система состоит из трех ключевых компонентов, координируемых через `APScheduler` в [scheduler.py](file:///Users/aleksandrposokhov/Life/HealVPN/bot/scheduler.py):

- **check_pending_payments**: Каждые 60 сек опрашивает YooKassa по незавершенным платежам из таблицы `pending_payments`.
- **auto_renew_subscriptions**: Каждые 15 мин проверяет пользователей, у которых заканчивается подписка (за 24 часа, 12 часов и 30 минут) и пытается провести автоматическое списание средств.
- **deactivate_expired_subscriptions**: Каждые 15 мин отключает пользователей с истекшим сроком подписки.

### Анализ устойчивости (Resilience) и самолечения (Self-Healing)
1. **Противодействие сбоям Marzban API**:
   - При автопродлении система сначала проверяет доступность Marzban (`token = await marzban_api.get_token()`). Если панель недоступна, списание средств пропускается до следующего цикла.
   - Если списание прошло успешно, но синхронизация с Marzban падает с исключением, платеж остается в таблице `pending_payments` и перепроверяется фоновым джобом каждые 60 секунд. Подписка активируется сразу после восстановления связи с Marzban.

2. **Предотвращение дублирования списаний (Идемпотентность)**:
   - Ключ идемпотентности YooKassa генерируется на основе ID пользователя, текущего срока окончания подписки и счетчика ошибок:
     `autorenew_{user.id}_{sub_end_ts}_{user.failed_payments}`
   - Это гарантирует, что в рамках одного платежного окна повторный запрос к YooKassa вернет тот же самый платеж, исключая повторные списания.

3. **Борьба с состоянием гонки (Race Conditions)**:
   - В [database.py](file:///Users/aleksandrposokhov/Life/HealVPN/bot/database.py) метод `activate_subscription` использует уровень изоляции транзакций и блокировку строки пользователя `with_for_update()`.
   - Если пользователь вручную нажимает «Проверить оплату» одновременно с работой фонового джоба `check_pending_payments`, транзакции сериализуются. Вторая транзакция увидит запись в `ProcessedPayment` и мгновенно откатится с `_AlreadyProcessed`, исключая двойную активацию или удвоение срока подписки.

## 2. Выявленные Улучшения (Defensive Programming & Performance)

Хотя текущая система крайне стабильна, мы внедрили следующие защитные улучшения для предотвращения потенциальных сбоев и оптимизации производительности:

1. **Безопасное чтение `metadata` в [payment_service.py](file:///Users/aleksandrposokhov/Life/HealVPN/bot/payment_service.py)**:
   - Если YooKassa вернет платеж с `metadata: null` или без этого поля, код `payment.get('metadata', {})` упал бы.
   - **Решение**: Заменено на `payment.get('metadata') or {}`.

2. **Безопасное чтение `amount` в [scheduler.py](file:///Users/aleksandrposokhov/Life/HealVPN/bot/scheduler.py)**:
   - Заменено на `(payment.get("amount") or {}).get("value", 111.0)`.

3. **Мьютекс и оптимизация блокировок SQLite в [database.py](file:///Users/aleksandrposokhov/Life/HealVPN/bot/database.py)**:
   - При высокой конкуренции фоновых проверок платежей и ручных нажатий кнопок SQLite мог вызывать ошибку `database is locked`.
   - **Решение**: Добавлен параметр `connect_args={"timeout": 30.0}` для ожидания освобождения БД и включен режим журнала **WAL (Write-Ahead Logging)** совместно с синхронизацией `PRAGMA synchronous=NORMAL`. Это позволяет одновременно читать и писать в базу без блокировок.

4. **Защита от ложных ошибок API в [marzban_api.py](file:///Users/aleksandrposokhov/Life/HealVPN/bot/marzban_api.py)**:
   - При первой синхронизации нового пользователя вызов `get_user()` приводил к ответу 404, который расценивался как ошибка HTTP и вызывал пугающие записи `ERROR:root:Error getting user from Marzban` в логах, хотя это нормальный статус проверки существования.
   - **Решение**: Добавлен прямой возврат `None` при ответе 404 без генерации исключения, делая логи чистыми и аккуратными.
